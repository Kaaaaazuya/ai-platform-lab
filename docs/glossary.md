# 用語集

このリポジトリのドキュメントで使う専門用語。新しい用語を使うときはここに足す（[文章ガイド](writing-guide.md)）。

## AI・LLM

| 用語 | 意味 |
| --- | --- |
| LLM | 大規模言語モデル。文章を生成するAIのモデル |
| AIゲートウェイ | アプリとLLMの間に置く中継役。認証、利用量の上限、モデルの振り分け、記録をまとめて受け持つ |
| RAG | 質問に関係するドキュメントを検索し、その内容を添えてLLMに回答させる方式 |
| 埋め込み（embedding） | 文章を数値の並び（ベクトル）に変換したもの。意味が近い文章ほど近い値になる |
| ベクトルストア | 埋め込みを保存し、近いものを検索できるデータベース。このリポジトリでは pgvector を使う |
| ストリーミング | 回答を全部できあがってから返すのではなく、生成した分から少しずつ返す方式 |
| フォールバック | 使いたいモデルが失敗したときに、別のモデルに切り替えること |
| ガードレール | LLMへの入力と出力を検査し、個人情報や危険な指示を止める仕組み |
| PII | 個人を特定できる情報。氏名、電話番号、メールアドレス、口座番号など |
| プロンプトインジェクション | 「これまでの指示を無視して」のように、LLMへの指示を書き換えようとする入力 |
| LLM-as-a-judge | 回答の良し悪しを、別のLLMに採点させる評価方法 |

## 観測・改善

| 用語 | 意味 |
| --- | --- |
| OpenTelemetry（OTel） | トレース、メトリクス、ログを集めるための標準規格とツール群 |
| OTLP | OpenTelemetryでデータを送るときの通信方式 |
| トレース | 1つのリクエストが通った処理の記録。画面からLLMまでの流れを1本でたどれる |
| span | トレースを構成する1つ1つの処理の記録。開始・終了の時刻と属性を持つ |
| Langfuse | LLMのトレース、評価、プロンプト、データセットを管理するツール |
| Grafana | メトリクスやログをグラフにして、死活監視とアラートを行うツール |
| 改善のアウターループ | 本番のトレースから問題を見つけ、評価データにして、直して、効果を確かめる繰り返し |

## AWS・基盤

| 用語 | 意味 |
| --- | --- |
| AWS Emulator | AWSのサービスを手元のマシンで再現するツール。2026年11月に公開された |
| Fidelity | AWS Emulatorが本物のAWSをどれだけ忠実に再現しているかの度合い |
| IaC | インフラの構成をコードで書いて管理すること。このリポジトリでは Terraform を使う |
| CI/CD | コードの変更を自動で検査（CI）し、自動で反映（CD）する仕組み |
| サンドボックス | アプリを他から隔離して動かす環境 |
| gVisor | コンテナとホストの間に入り、コンテナからホストへの影響を抑える仕組み |

## 開発・セキュリティ

| 用語 | 意味 |
| --- | --- |
| ADR | 設計上の判断を、理由とともに1件ずつ記録したドキュメント |
| サプライチェーン攻撃 | 依存しているパッケージやツールに悪意のあるコードを紛れ込ませる攻撃 |
| install スクリプト | npmパッケージのインストール時に自動で実行される処理。サプライチェーン攻撃の入口になりやすい |
| cooldown | 新しい版が公開されてから、更新を提案するまで待つ期間 |
| fail-open | 検査の仕組みが失敗したときに、止めずに処理を続ける動き方 |

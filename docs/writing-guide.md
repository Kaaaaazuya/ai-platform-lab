# 文章ガイド

このリポジトリで人が読む文章（デザインドック、ADR、セットアップ手順、README、PRの説明）を書くときの決まり。

## 前提

- 文章は読まれるために書く。主な読者は人間である
- 文章を書く作業は「内容と構造の設計」と「執筆」に分かれる。執筆はAIに任せてよい。設計は、人が読者を想定して行う
- AIが書いた文章の読みにくさは、たいてい次の2つから来る
    - 書かなくてよいことまで書いている
    - 形式がドキュメントの目的と合っていない
- AIに書かせた文章も、AIの見直しに加えて最後は人が読んで直す。説明できない文章は出さない

## ドキュメントごとに書くこと・書かないこと

| ドキュメント | 読者 | 書くこと | 書かないこと |
| --- | --- | --- | --- |
| デザインドック（`docs/index.md`） | 全体像を知りたい人、未来の自分 | 目的と背景、システム構成図、シーケンス図、データの入出力の概要、異常系と影響範囲、セキュリティ上のリスク | ファイル名・関数名・変数名、実装を日本語に直しただけの説明、サンプルコード |
| ADR（`docs/adr/`） | 判断の経緯を知りたい人 | 判断が必要になった状況、選択肢と長所・短所、決定とその理由、受け入れること、確認すること | 決定と関係のない実装の詳細 |
| セットアップ手順（`docs/setup.md`） | 手元で動かす人 | 前提、コマンド、確かめ方、まだ確かめていないこと | 設計の理由（ADRへのリンクで済ませる） |
| README | リポジトリを初めて見た人 | 何のリポジトリか、構成の一覧、すぐ動かす手順、ドキュメントへのリンク | デザインドックと重複する説明 |
| PRの説明 | レビューする人 | 何を変えたか、なぜ変えたか、レビューで見てほしいこと、確かめていないこと | 差分を読めば分かる変更の羅列 |

ADRは決定の記録なので、設定ファイル名や環境変数名を書いてよい。デザインドックには書かず、必要ならADRへリンクする。

## 書き方

<!-- 2. の例は表記ゆれそのものを示すので、この一覧だけ表記の統一を検査しない -->
<!-- textlint-disable prh -->

1. **平易で一般的な用語を使う**：新しく入ったメンバーにも分かる言葉を選ぶ。専門用語は[用語集](glossary.md)に載せ、初出でリンクする
2. **用語を統一する**：同じものを別の言葉で呼ばない（例：「ドキュメント」と「文書」、「IPアドレス」と「IP」）。製品名の大文字・小文字と全角・半角もそろえる。表記は `prh.yml` で機械的に確かめる
3. **一文を長くしすぎない**：一文は100文字までにする。長くなったら文を分ける。長さはtextlintで確かめる
4. **箇条書きを使う**：時系列の手順や、並列の項目に使う。理由や経緯のように前後がつながる内容は文章で書く
5. **章構成を先に決める**：見出しを階層にして、先に目次（見出しの箇条書き）を作ってから中身を書く
6. **図を使う**：構成図・シーケンス図・フローはMermaidでコードとして管理する。込み入ってきたら専用の作図ツールに切り替える
7. **早めに相談する**：完成してから見せない。半分くらいの段階でドラフトのPRを出し、判断する人に見てもらう
8. **読者を想像する**：読者によって書く内容と書き方を変える。AIに書かせるときも読者を指定する
9. **知ったかぶりをしない**：分からないこと、確かめていないことは、そう書く。各ドキュメントの「確認すること」「まだ確かめていないこと」に残す
10. **最後は自分を信じる**：調べて、相談して、吟味したものは自信を持って出す

## AIに書かせるときの指示

AIに文章を書かせるときは、次を指示に含める。

- 読者は誰か、読んだ後に何をするか
- 新しく入ったメンバーにも分かる言葉を使い、専門用語は用語集にあるものを使う
- 同じものを指す言葉を統一する
- 一文は100文字まで
- 上の表の「書かないこと」は書かない

## 機械的なチェック

文章のリンターとして [textlint](https://textlint.org/) を使う。

- ルール：[textlint-rule-preset-ja-technical-writing](https://github.com/textlint-ja/textlint-rule-preset-ja-technical-writing)（一文の長さ、読点の数、助詞の重複、文末の句点など）
- 表記の統一：`prh.yml` の辞書（textlint-rule-prh）
- 対象：`README.md` と `docs/` 以下のMarkdown
- 実行：`npm run lint:text`。コミット前のフック（lefthook）とCIでも動く

どうしてもルールに合わない箇所は、理由を書いたうえで、コメントを使って一時的に無効にする。

```markdown
<!-- textlint-disable ja-technical-writing/sentence-length -->
（URLを含む長い文など）
<!-- textlint-enable ja-technical-writing/sentence-length -->
```

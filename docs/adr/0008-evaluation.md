# ADR-008 評価の仕組み

ステータス: Proposed（未決定）

## コンテキスト

改善ループの要は、変更前後を同じデータセットで比べること。評価をどのツールで行い、判定役のモデルをどれにするかを決める。

## 選択肢

| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| A | LangfuseのデータセットとLLM-as-judge | 観測と評価が1か所にまとまる | CIとの連携は自分で組む |
| B | promptfoo | CIで回しやすく、設定ファイルで管理できる | 結果がLangfuseと分かれる |
| C | Ragas | RAG向けの指標がある | 単独では運用の仕組みがない |

## 判断材料・確認すること

- [ ] 判定役のモデル：Ollamaで十分か、Bedrockが必要か
- [ ] 評価データセットの初期件数と作り方（ADR-009と連動）
- [ ] OTelトレースのどのspanにどの評価をかけるか（検索spanに関連性、生成spanに根拠の有無など）と、サンプリング率
- [ ] CIの合格条件に入れるレイテンシ・コストのしきい値

未定。

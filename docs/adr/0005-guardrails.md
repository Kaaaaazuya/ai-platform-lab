# ADR-005 ガードレールの実装位置とログ方針

ステータス: Proposed（未決定）

## コンテキスト

PIIマスクとプロンプトインジェクション検知をどこで強制するかを決める。UberはゲートウェイにPIIマスクを組み込んでいるが、入力が長いほどレイテンシが増えると報告している。あわせて、プロンプト本文をログにどう残すかも決める。

## 選択肢

| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| A | ゲートウェイのガードレール連携でPresidioなどを呼ぶ | 1箇所で必ず通る | レイテンシが増える |
| B | LLM Guardなどを別コンテナ（サイドカー）として置く | 差し替えやすい | 通信が1ホップ増える |
| C | 実AWSではBedrock Guardrailsを使う | マネージド | ローカルで再現できない |

**ログ方針の候補**：本文を記録する / マスク後のみ記録する / メタデータのみ記録する

## 判断材料・確認すること

- [ ] 日本語のPII（氏名、住所、口座番号など）をどこまで検出できるか試す
- [ ] 改善ループには本文が必要なので、マスクとの両立方法を決める
- [ ] ストリーミングで表示した後に出力検査で引っかかった場合の扱い（表示済みの回答を差し替えるか、チャンクごとに検査するか）。ADR-011より
